# Notes for Claude

- Owner: Kelly. She works on Windows and plays the game through GitHub Pages. Do not use em dashes in user-facing text or docs.
- Stack: Vite + TypeScript, plain Canvas 2D (no game framework). Isometric view, action combat (WASD + mouse aim), AUTO pilot with manual override.
- Characters: 3 save slots (`idle-rpg-char-0..2` in localStorage), jobs Warrior/Archer/Mage defined in `JOBS` (data.ts). Skills are data-driven by `SkillType`; implement new types in `Game.castSkills`. Sim per job: `npm run sim -- 4 archer`.
- World: one connected map (`generateWorld` in map.ts), zones in `ZONES` (data.ts), mobs are tagged with a zone and can't cross Gate tiles (pass `mob = true` to map collision/path helpers). Bosses live in lairs (`generateLair`, separate map; `Game.enterLair/exitLair` swap the map and keep world mobs) and are summoned at the lair's circle in order (`bossesCleared`). Summon offerings: `ZONES[z].offering` + `state.items` (empty for now, future item system). The old stage/kills fields in state are unused leftovers.
- Boss difficulty is intentional (Souls-like): %max-HP boss hits, phases, enrage, flasks, imperfect AUTO dodging. Validate changes with `npx tsx tools/bosstrial.ts <job> [zone]` (AUTO should lose at equal level; skilled should usually win) and `npm run sim -- 30 warrior` (AUTO-only journey: boss 1 ~5h, boss 2 ~11h, boss 3 needs a human).
- Boss 1 (King Jelly, `bossSplit` in `ZONES`) splits at each phase: 1, 2, then 4 slimes sharing one HP pool (`SPLIT` in data.ts: smaller, faster, softer hits; multi-slime hits have diminishing returns). `Game.splitGroup`, `splitSlime`, `checkPhase`; killing the pool kills every slime. The original is the crowned main slime (`isMainSlime`) and aims right at the player; split-offs aim via `chaosPoint` (lead the player using `pVel`, or random spots nearby) with jittered timing so attacks don't stack. In phases 1-2 the main slime hops around the room (landing telegraphs have `style` 'wave' for the crowned slime / 'landing' for split-offs: faint outline, fill grows with the jump's travel time, dotted line from the slime in the air; 'wave' adds a second outline) (`updateMainHopper`, `roomSpot`: random open spots at least 220 from you, marked slam landing); each landing sends out slime `waves` (expanding rings with `SPLIT.waveGaps` safe gaps, hit once, and a hit slows you to 50% for 2 s via `slowUntil`; rings per landing `SPLIT.waveCount` = 2 in phase 1, 3 in phase 2, `waveSpacing` apart, each with gaps shifted from the last). It won't jump again until its last ring is `SPLIT.waveRest` of the way out. Every hit from the crowned slime (rings, slams, cut-offs, charges, globes) adds a Slimed stack (`addSlime`, `slimeStacks`, shown under the boss bar); `SPLIT.waveLethal` (10) in one fight kills you. Lair has P2/P3 summon buttons for testing (`summonBoss(phase)`, `skipToPhase`). AUTO slides toward a gap (`waveDodge`). Its specials are `cutoff`/`charge`/`cone`. Split-offs hop (`updateHopper`, `SPLIT.kit` = charges + circle barrages), leave goo (`Game.goo`, 7 s) and bumping them or standing in goo roots the hero (`rootPlayer`). No grace by design (Kelly's call): `SPLIT.rootImmune` is 0, goo that roots you is used up (every puddle you're touching splats away), bumps re-root with no immunity, and hits while rooted deal +30%. Mid-air drops skip the spot you stand on, so every root is avoidable. Phases at 80% / 50% (`phaseAt` in `ZONES`) so the four-slime phase is the long one. In the last phase (the wild phase, `SPLIT.wild`) the main slime leaps to the arena centre and bounces in place (`updateAnchored`) while the minis go wild: their jumps, charges and barrages target random spots anywhere in the room (`roomSpot`, not the player), hop every 0.15-0.45 s, specials ~3x as often, charge-heavy kit, charges up to 900 long at 1250 speed, bigger puddles, denser charge trails, `gooMax` 280, red aura. Random targeting made phase 3 easier than phase 2 for the bot (at +3 levels nearly always wins); Kelly was told and may want aimed attacks or globes mixed back in. The globes are off (`SPLIT.wild.globes`); when on they drop in a checkerboard of 2x2-tile squares (`SPLIT.globeCell`, telegraph kind `square`); each volley flips which squares get hit (`globeParity`), so players can plan. Each square shows a darkening shadow and the globe falling (`drawFallingGlobes`). AUTO heads for the nearest safe square (`Game.safeSpots`). Telegraphs with the same `volley` id hit at most once. A hit that skips a threshold still does every skipped split. AUTO steers around goo (`avoidGoo`/`sticky`). Boss attacks are clamped to the arena (`clampArena`, `chargeLength`). Current state (Kelly wants it this hard): at equal level the skilled bot dies in phase 2 (the double rings); at +3 levels it usually reaches phase 3 and dies there (phase 3 is meant to be the main show); +6 levels wins.
- Dying to a boss (browser only, `game.offerRetry` set in main.ts) waits on a choice (`retryZone`, `awaitingChoice`, `#deathbox`): `retryBoss(phase)` (full HP and flasks, fresh boss at once, optionally starting in phase 2 or 3 with its HP at that threshold) or `respawnNow()`. The sim/bosstrial leave `offerRetry` false and auto-respawn as before.
- Collision: `fits` (map.ts) samples a grid no coarser than half a tile, because bosses are wider than a tile (a corners-only check let them straddle pillars and freeze). `Game.depenetrate` pushes any mob that overlaps a wall back out, and blocked mobs try turning to slide around corners. Charges and hop landings use the walking radius (`m.r * 0.8`).
- Space ability per job (`JOBS[j].evade`, tuning in `EVADE`, 10 s cooldown): Warrior Parry (`parryUntil`; the next hit or root is ignored and `counter()` hits everything nearby for 3x ATK), Archer Sprint (`sprintUntil`, +60% speed for 3 s), Mage Blink (240 units toward movement or aim, needs floor and line of sight, breaks roots). `Game.useEvade`; AUTO uses it while dodging (`autoEvade`). Attack is click or J (Space no longer attacks).
- Prediction: `cutoff` boss move (all bosses' later phases and the split-off kit) puts a line of circles across where you're running plus one further ahead (boxes you in if you stand still); main bosses' `slam` leads your movement 40% of the time. Both use `pVel`.
- Performance: `window.__perf` shows rolling ms per frame (game/ui/draw). HUD writes go through `setText`/`setStyle` in ui.ts (DOM touched only on change). `findPath` reuses buffers with a binary heap; keep per-frame allocations out of the renderer.
- Power comes mainly from level (`LEVEL_POWER`, data.ts); Growth upgrades are % multipliers. Boss HP is per zone (`BALANCE.bossHpMult[]`).
- Talents: `TALENT_TREES` (data.ts), state.talents, `talentStats`/`talentBlocked` (stats.ts), procs in game.ts (`damage`, `playerAttacks`, `tickDots`, `startSkill`, `hurtPlayer`). Mage has mana (`MANA`) and Arcane Charges. Boss HP per zone assumes the talent points you'd have by then; the sim and bosstrial auto-assign talents.
- Spec cores: each spec should feel like its own class. Marksman = Focus/Deadeye (`FOCUS`, `Game.activateDeadeye`, `empoweredShot`). All talent stats are listed in `TALENT_STATS` and start at 0 (never reference a stat that isn't in that list).
- Echoing Hollow: manual-only cave (`generateCave`, `Game.enterCave/exitCave`, `inCave` forces `auto` false). Cave mobs use zone id `CAVE.zone` (99) and scale to the player's level.
- Monsters come from fixed spawn camps per zone (even level spread). AUTO avoids monsters 4+ levels above you and roams to level-appropriate camps.
- Layout: full-screen canvas with floating HUD panels (index.html `#battle`). Menus are windows (`#window`) opened from the bottom-right buttons (`UI.openWindow/closeWindow`, Esc closes). Phones/narrow screens (`pointer: coarse` or < 720px) stack the HUD at the top, menu buttons on the right, windows as a bottom sheet; the renderer's `compact` getter moves the boss bar/minimap to match.
- `main` is the isometric game. The old side-scroller lives on the `side-scroller` branch and deploys to /side/; leave it alone unless asked.
- Planned: replace gacha with an ironman-style gear system (work for everything; drops are the only RNG). Long-term goal is a low-grind MMO. Keep `src/game.ts` free of DOM code so `npm run sim` keeps working.
- Balance lives in `src/data.ts` (`BALANCE` and the content tables). After balance changes, run `npm run sim -- 6` and check pacing.
- New save fields must get defaults in `newState()` and survive `migrate()` so existing players never lose progress.
- Original content only: no MapleStory/Nexon names, sprites, maps or music. Mechanics may be similar.
- Before pushing: `npm run build` must pass (it runs `tsc`).
- Pushing to `main` deploys automatically.
